## 当前里程碑

- `cases.json` 收录 **21个不同子任务**；[证据索引](<证据索引.csv>)由 `build_evidence_index.py` 生成，21行均有实际平台代理通过的后测。与无技能基线及宿主机精确复评分组配对，**13个不同编号**有已评分失败的前测及平台通过的后测。其中 **10个可辩护的修复候选**：`1-3/2`、`1-4/2`、`1-4/3`、`1-5/2`、`1-11/0`、`1-11/1`、`1-12/0`、`1-13/2`、`1-18/1`、`1-23/0`；`1-5/2` 的日薪计算依赖人工确认分项为年薪。另三题 `1-6/2`、`1-6/4`、`1-9/2` 仅是时间/百分比文本降级或单位歧义下的评分兼容，不计无保留修复。`1-3/4`、`1-6/3` 有真实但未配对的评分失败，因题意与评分冲突，不做错误操作来迎合评分。事后选题不能推出总体修复率。
- 教师 Next 页 `/officebench-week4` 已通过 Edge 实际交互验证：水合后8节点、9条边；点击运行 `1-3/0` 通过并显示节点证据，重载清空结果而保留图。见 [截图](<platform-interactive.png>)和[脱敏记录](<platform-interactive-evidence.txt>)。HTTP代理对21个不同任务经 **Next→实际 Spring `FlowCodeRun` 类覆盖→Python桥接** 均返回通过，后测保存在 `bridge-runs/`。这是冻结图的本机受限转发，不是教师平台注册中心原生动态技能调度。

## 证据与边界

[问题清单](<问题清单.md>)逐题解释失败机制与前后对应；[评分冲突分析](<新增筛选与评分冲突.md>)区分题面冲突、兼容结果和评分环境故障。`1-11/0`、`1-11/1` 的参考答案只在宿主机复评和后测核验使用，未暴露给无技能代理；两题经宿主机复评确为失败，不能因旧Docker适配器缺参考文件而作废。`1-14/0` 原始试跑的失败仅由缺参考文件造成，宿主机复评为通过，不计失败；`1-15/0` 存在输入 `House_creak.docx` 与评分器 `house_creak.docx` 大小写不一致，`1-19/0` PDF转DOCX缺产物，均未纳入修复候选。

人工结构按输入定位、意图分支、文件或表格操作、路径规范化、原生条件与语义双验收、条件写回执行。同文件写入串行，独立只读核验可并行；冲突写入拒绝合并，验收不通过不写回。下阶段 LLM 只能提议带类型与权限约束的结构；隐藏参考与评分配置只供离线验收，结构须经静态校验、隔离运行及未见任务验证。当前里程碑是**有条件完成10个配对修复候选的本机验证**，并非证明LLM自动编排或官方完整评测通过。
