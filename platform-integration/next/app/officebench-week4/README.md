# OfficeBench Week 4 mounted route

`/officebench-week4` is a mounted adaptation of `../../week4-officebench/platform-integration/page.tsx` and its CSS. The standalone page remains untouched and owns the original design. Next's static export and the app's TypeScript compilation must resolve all imports locally; this route uses a snapshot (`frozen.ts`) of the public node/edge/case metadata in `../../week4-officebench/structure.json` and `../../week4-officebench/cases.json`. Regenerate that snapshot when either source changes; do not edit the standalone source to customize this mount. The source files contain additional data not shipped to the browser, such as data paths, which is why the snapshot contains only IDs, kinds and skills.

Clicking Run sends `flowRun({structure: JSON.stringify({case_id,graph})})`. The existing client wraps this in POST `/skillTesting-core/api/engine/flow` with flow ID `@com.horsecoder.common.whuTalent.skillTesting.core/FLOW_RUN`. The UI parses `data.value.result` as serialized execution evidence and displays before/after, events and artifacts. The development-only rewrite in `next.config.ts` points `/skillTesting-core` at Spring `127.0.0.1:33477`; Spring forwards validated requests to the Week 4 localhost bridge. There is no arbitrary URL or file path input on this route. A static export alone cannot execute this call; it requires a proxy/runtime route and a running backend and bridge. No server is started by the mount.
